# Project boundaries

Every project declares **exactly one scope tag** in its `package.json`
(`nx.tags`). The scope decides which projects it may depend on.

| Scope            | Projects                                     | May depend on              |
| ---------------- | -------------------------------------------- | -------------------------- |
| `scope:frontend` | `apps/crm-web`, `packages/frontend/*`        | frontend, shared           |
| `scope:backend`  | `apps/auth`, `apps/crm-api`, `packages/backend/*` | backend, shared        |
| `scope:shared`   | `@dafne/contracts`, `@dafne/auth-options`    | shared only                |
| `scope:tooling`  | `@dafne/cli`                                 | tooling only               |

## The main rule: only the backend reaches the database

The frontend talks to the backend **over HTTP** and never imports a backend
package, **not even for types**. What both sides need (request schemas,
response types, Better Auth's user fields) lives in a shared package:

- `@dafne/contracts`: Zod schemas and response types of the API.
- `@dafne/auth-options`: Better Auth options; the frontend imports only
  their type.

Shared packages may only depend on other shared packages, so they stay free
of Nest, Node and database code.

## Where the rules are written

In one place: **`tools/boundaries.mjs`** (`DEP_CONSTRAINTS`). Two checks
read it:

| Check                                   | What it covers                                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------ |
| ESLint `@nx/enforce-module-boundaries`  | The frontend's imports, while editing (`packages/frontend/eslint.config.mjs`)                     |
| `pnpm boundaries` (`tools/check-boundaries.mjs`) | Every project, from the Nx project graph: imports **and** `package.json` dependencies. Also fails when a project has no scope tag or more than one. Runs in CI. |

The backend lints with oxlint, which has no boundaries rule: that's why the
graph check exists.

## New projects

Projects generated by the CLI get their tag (`scope:backend`,
`scope:frontend`). A project created by hand needs one in `nx.tags`, or
`pnpm boundaries` fails.
